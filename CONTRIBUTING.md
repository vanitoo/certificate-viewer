# Участие в разработке

## Подготовка окружения

Требуется Node.js 22 и npm.

Пока публичный `package-lock.json` не регенерирован, используйте:

```bash
npm install --registry=https://registry.npmjs.org
```

После исправления lock-файла проект вернётся к стандартной установке `npm ci`.

## Правила изменений

1. Создавайте отдельную ветку с небольшим, сфокусированным изменением.
2. Не добавляйте сетевые запросы, аналитику, cookies или крупные зависимости без архитектурного обоснования.
3. Не описывайте структурный разбор сертификата как подтверждение доверия.
4. Для изменений парсера проверяйте пустые, повреждённые, нестандартные и слишком большие файлы.
5. Новые функции парсера должны оставаться независимыми от React.
6. Обновляйте README, CHANGELOG, TODO и архитектуру, когда меняется поведение, безопасность или процесс выпуска.

## Проверка перед pull request

```bash
npm run check
npm audit --omit=dev --audit-level=high --registry=https://registry.npmjs.org
```

После появления тестов они должны входить в единую команду `npm run check`.

## Структура проекта

- бизнес-логика и UI просмотрщика: `src/features/certificate-viewer`;
- общие layout-компоненты: `src/components`;
- приложение и metadata: `src/app`;
- архитектурная и security-документация: `docs`.

Уязвимости сообщайте по правилам из [SECURITY.md](SECURITY.md), а не через публичные issues.
