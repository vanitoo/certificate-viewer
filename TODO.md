# План развития

Roadmap отражает фактическое состояние проекта. Выполненные задачи не удаляются, чтобы было видно, что уже входит в текущий MVP.

## Выполнено

- [x] локальный browser-only интерфейс без сервера, регистрации, cookies и аналитики;
- [x] поддержка PEM, DER, CER и CRT;
- [x] автоматическое определение PEM/DER по содержимому;
- [x] разбор нескольких сертификатов в PEM bundle;
- [x] основные поля X.509: Subject, Issuer, версия, серийный номер и даты действия;
- [x] алгоритм подписи и сведения об открытом ключе;
- [x] отображение расширений, OID, `critical` и Subject Alternative Name;
- [x] отпечатки SHA-256 и SHA-1 через Web Crypto;
- [x] предупреждения о сроке действия, SHA-1, слабом RSA и self-signed;
- [x] копирование значений и PEM;
- [x] экспорт PEM и JSON;
- [x] Drag & Drop, `Ctrl+O` / `Cmd+O` и адаптивный интерфейс;
- [x] ограничения 10 МБ на файл, 2 МБ на сертификат и 100 сертификатов на bundle;
- [x] строгая проверка Base64 для PEM;
- [x] статическая публикация в GitHub Pages;
- [x] CI, CodeQL, `npm audit`, Dependency Review и Dependabot;
- [x] ограничение Dependabot обновлениями minor/patch;
- [x] обновление основных GitHub Actions до актуальных major-версий;
- [x] Vitest и unit-тесты основного парсера;
- [x] тест валидного PEM, валидного DER и PEM bundle;
- [x] тесты пустого файла, повреждённого Base64 и повреждённого DER;
- [x] тесты лимитов 10 МБ, 2 МБ и 100 сертификатов;
- [x] fixtures для valid, expired, not-yet-valid, SHA-1 и RSA-1024;
- [x] тесты статусов expired и not-yet-valid;
- [x] тесты предупреждений SHA-1 и слабого RSA;
- [x] тесты Distinguished Name, известных расширений, `critical` и неизвестного OID;
- [x] тестовые сертификаты вынесены из test-файла в каталог `__fixtures__`;
- [x] запуск unit-тестов внутри `npm run check`.

## Не планируется для browser-only версии

- автоматический доступ к системному хранилищу сертификатов Windows/macOS/Linux;
- извлечение TLS-сертификата произвольного сайта напрямую из обычной веб-страницы;
- онлайн-проверка OCSP/CRL без отдельного сетевого режима;
- хранение или экспорт приватных ключей без отдельной модели угроз и явного пользовательского сценария.
