# Certificate Viewer

Локальный browser-only просмотрщик X.509-сертификатов. Приложение открывает PEM, DER, CER и CRT прямо в браузере: файлы не загружаются на сервер, не сохраняются и не покидают устройство.

**Онлайн-версия:** <https://vanitoo.github.io/certificate-viewer/>

## Статус проекта

Текущая версия: **0.2.0**. Основной MVP готов и опубликован в GitHub Pages.

Certificate Viewer подходит для быстрого просмотра структуры сертификата, но пока не заменяет полноценную PKI-валидацию: приложение не проверяет доверие системного хранилища, отзыв через OCSP/CRL и криптографическую цепочку доверия.

## Возможности

- просмотр одиночных сертификатов и PEM bundles;
- автоматическое определение PEM или DER по содержимому;
- Subject, Issuer, версия X.509, серийный номер и срок действия;
- алгоритмы подписи и открытого ключа;
- расширения X.509 с отображением OID и признака `critical`;
- Subject Alternative Name;
- отпечатки SHA-256 и SHA-1;
- предупреждения о просрочке, будущем начале действия, SHA-1, слабом RSA-ключе и self-signed сертификате;
- копирование значений и PEM;
- экспорт сертификата в PEM и результата разбора в JSON;
- Drag & Drop, выбор файла и горячая клавиша `Ctrl+O` / `Cmd+O`;
- адаптивный интерфейс;
- полностью статическая публикация в GitHub Pages.

## Ограничения

- максимальный размер входного файла — 10 МБ;
- максимальный размер одного сертификата — 2 МБ;
- не более 100 сертификатов в одном PEM bundle;
- PFX/P12, CSR и CRL пока не поддерживаются;
- подпись и цепочка доверия пока не проверяются;
- ASN.1 разбирается в основном UI-потоке, поэтому специально сформированный файл теоретически может временно заблокировать интерфейс.

> Успешный разбор означает только то, что структура сертификата распознана. Это не подтверждение доверия или безопасности сертификата.

## Технологии

- Next.js 16 и React 19;
- TypeScript в строгом режиме;
- PKI.js и ASN1.js;
- Web Crypto API;
- Tailwind CSS 4;
- статический экспорт без серверной части.

## Локальный запуск

Требуется Node.js 22 и npm.

```bash
npm install --registry=https://registry.npmjs.org
npm run dev
```

Откройте <http://localhost:3000>.

Полная проверка проекта:

```bash
npm run check
```

Статическая сборка создаётся в каталоге `out/`:

```bash
npm run build
npx serve out
```

### Временное ограничение lock-файла

Текущий `package-lock.json` был создан в среде с внутренним npm mirror и требует регенерации через публичный `registry.npmjs.org`. До исправления CI использует установку из публичного registry без lock-файла. Это зафиксировано первым пунктом в [TODO](TODO.md).

## GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` автоматически публикует ветку `main`.

В настройках репозитория должно быть выбрано:

**Settings → Pages → Source: GitHub Actions**

Для project page базовый путь вычисляется из `GITHUB_REPOSITORY`, поэтому ресурсы корректно загружаются по адресу `/certificate-viewer/`.

## Безопасность и приватность

- нет API routes и серверной части;
- нет регистрации, cookies, аналитики и телеметрии;
- нет сетевой отправки пользовательских файлов;
- значения отображаются React как текст;
- `dangerouslySetInnerHTML` не используется;
- CI выполняет typecheck, lint и production build;
- Security workflow запускает `npm audit`, CodeQL и Dependency Review;
- Dependabot ограничен minor/patch-обновлениями.

Подробнее: [SECURITY.md](SECURITY.md) и [docs/SECURITY_AUDIT.md](docs/SECURITY_AUDIT.md).
