# Аудит безопасности

Дата: 2026-07-20  
Область: клиентский код, цепочка сборки, зависимости и GitHub Actions.

## Итог

Критических и high-severity проблем в просмотренном коде и production dependencies не обнаружено. Приложение обрабатывает файлы локально, не выполняет пользовательский HTML и не отправляет сертификаты по сети.

## Исправлено в 0.2.0

| Риск | Мера |
| --- | --- |
| CPU/память DoS через большой PEM bundle | Лимит 100 сертификатов и 2 МБ на сертификат поверх общего лимита 10 МБ |
| Некорректный или двусмысленный PEM | Строгая валидация Base64 до ASN.1-разбора |
| Уязвимые зависимости | Еженедельный и PR-запуск `npm audit` с порогом high, Dependabot |
| Уязвимости JavaScript/TypeScript | CodeQL на push, PR, по расписанию и вручную |
| Опасное изменение dependency graph | Dependency Review блокирует high/critical на PR |
| Избыточные права Actions | Явные минимальные `permissions`; права Pages назначены только deploy job |
| Уязвимости Next.js 16.1.4 | Next.js и ESLint config обновлены до 16.2.10; high-severity findings устранены |

## Остаточные риски

- ASN.1 разбирается в основном UI-потоке. Ограничения уменьшают риск, но специально созданный небольшой файл все еще может вызвать дорогой разбор. Рекомендуется Web Worker с тайм-аутом.
- GitHub Pages не позволяет задавать пользовательские HTTP security headers. CSP через HTTP-заголовок следует добавить при переходе на подходящий хостинг; meta-CSP не добавлена, чтобы не создавать ложное ощущение полной защиты.
- Просмотрщик не проверяет криптографическую подпись, доверенную цепочку и отзыв. Это явно отмечено в интерфейсной документации.
- SHA-1 рассчитывается только как справочная fingerprint и не используется как критерий доверия.
- `npm audit` сообщает moderate advisory во вложенном PostCSS Next.js. Исправленной совместимой версии пока нет; приложение не передает пользовательские CSS-данные в PostCSS и публикуется как статический результат сборки. Workflow продолжит блокировать новые high/critical findings.

## Автопроверки

Security workflow запускается для pull request и `main`, еженедельно по понедельникам и вручную. Перед релизом также выполняются `npm run check` и production-only audit зависимостей.
