# Аудит безопасности

Дата первоначального аудита: 2026-07-20  
Последнее обновление: 2026-07-24  
Область: клиентский код, обработка входных файлов, цепочка сборки, зависимости и GitHub Actions.

## Итог

Критических и high-severity проблем в просмотренном клиентском коде и production dependencies не обнаружено. Приложение обрабатывает сертификаты локально, не выполняет пользовательский HTML и не отправляет файлы по сети.

При этом текущая версия является просмотрщиком структуры X.509, а не полноценным валидатором доверия.

## Реализованные меры

| Риск | Мера |
| --- | --- |
| CPU/память DoS через большой файл | Общий лимит 10 МБ |
| CPU/память DoS через PEM bundle | Лимит 100 сертификатов и 2 МБ на отдельный сертификат |
| Некорректный или двусмысленный PEM | Строгая проверка Base64 до ASN.1-разбора |
| Выполнение пользовательского HTML | Значения отображаются React как текст, `dangerouslySetInnerHTML` не используется |
| Утечка сертификатов | Нет API routes, `fetch`, аналитики, телеметрии и сохранения файлов в браузерное хранилище |
| Уязвимые зависимости | `npm audit`, Dependabot и Dependency Review |
| Уязвимости JavaScript/TypeScript | CodeQL на push, pull request, по расписанию и вручную |
| Избыточные права Actions | Явные минимальные `permissions`; права Pages назначены только deploy job |
| Устаревшие версии Actions | Основные Actions обновлены до актуальных major-версий |
| Шумные major-обновления | Dependabot ограничен minor/patch-обновлениями |
| Уязвимости Next.js 16.1.4 | Next.js и ESLint config обновлены до 16.2.10 |

## Остаточные риски

### Парсинг в UI-потоке

ASN.1 пока разбирается в основном потоке. Ограничения размера уменьшают риск, но специально сформированный небольшой файл всё ещё может вызвать дорогой разбор. Рекомендуется Web Worker с тайм-аутом и отменой операции.

### Неполная PKI-валидация

Просмотрщик не проверяет:

- криптографическую подпись загруженным issuer;
- построение доверенной цепочки;
- системное хранилище доверенных корней;
- отзыв через OCSP/CRL.

Интерфейс и документация не должны описывать успешный структурный разбор как подтверждение доверия.

### SHA-1

SHA-1 рассчитывается только как справочный fingerprint и не используется как критерий доверия.

### GitHub Pages и CSP

GitHub Pages не позволяет задавать произвольные HTTP security headers. CSP через HTTP-заголовок следует добавить при переходе на подходящий хостинг. Meta-CSP намеренно не выдаётся за полноценную замену заголовка.

### Lock-файл и воспроизводимость сборки

Текущий `package-lock.json` содержит URL внутреннего npm mirror среды первоначальной сборки. GitHub Actions временно устанавливают зависимости напрямую из публичного registry без lock-файла.

Это устраняет недоступность пакетов, но снижает воспроизводимость сборки. Приоритетное исправление:

1. регенерировать lock-файл через `registry.npmjs.org`;
2. проверить отсутствие внутренних URL;
3. вернуть `npm ci` и npm cache во все workflow.

### Автоматические тесты

Unit-тесты парсера и fixtures пока отсутствуют. До их появления регрессии выявляются TypeScript, ESLint, production build и ручной проверкой. Добавление тестов повреждённых ASN.1/PEM и граничных лимитов является задачей P0.

### Вложенные advisories

`npm audit` может сообщать moderate advisory во вложенном PostCSS Next.js. Приложение не принимает пользовательские CSS-данные и публикуется как статическая сборка. Workflow продолжает блокировать high/critical findings.

## Автопроверки

- CI: pull request и push в `main`;
- Security: pull request, push в `main`, еженедельно по понедельникам и вручную;
- Pages: push в `main` и ручной запуск;
- Dependabot: еженедельные minor/patch-обновления npm и GitHub Actions.
